# TRIP-010 Flight search results: solution

How it is built. What is built and why (goal, scope, requirements) is in the card: `gh issue view 15`. How it works in more detail is in [wiki/system/search-results.md](../../wiki/system/search-results.md).

## Data

Migration `db/migrations/007_all_routes.sql`, generated by `scripts/generate-all-routes.mjs` (fixed seed 2010, so it is the same every time; a unit test regenerates it and compares):

- `ALTER TABLE routes DROP COLUMN aircraft_id` (R12). SQLite allows dropping a column with a foreign key to another table; checked on a copy of the local database, where routes had aircraft.
- `ALTER TABLE route_departures ADD COLUMN price INTEGER CHECK (price BETWEEN 150 AND 1000000)` (R11). The column can't be `NOT NULL` without a default; the unit test checks that every departure has a price.
- `ALTER TABLE airports ADD COLUMN city TEXT`, set for all 51 airports (for R5's "IATA code and city"; the table had no city).
- The 200 old routes keep their id, flight time and departures; each gets a price per departure, and new departures up to 5, at least an hour from the others. 2 350 new routes (ids 201–2550) for the remaining ordered pairs, also closer than 150 km, with the same flight time formula and 5–7 departures, one in each equal part of 06:00–21:30 (R10).
- Prices: a share of 0.8 / 0.1 / 0.1 picks the range 150–5 000, 5 000–100 000 or 100 000–1 000 000 kr, and the price is uniform in it, rounded to tens.

`scripts/generate-routes.mjs` was refactored to export its airports, `distanceKm`, `flightMinutes`, `seededRandom`, `formatTime`, `q` and `generateRoutes()` (the 200 routes with their departures), and to print only when run. Its output is byte for byte the same (TRIP-005-R5's unit test).

The migration is about 1 MB of SQL and runs in a fraction of a second locally.

## Interface

- **`app/components/SearchForm.tsx`** (R1, R2): a submit button **Sök** (`Button`, `md:h-14.5` to match the fields), messages for missing values after the first press ("Välj var du vill flyga från.", "Välj vart du vill flyga.", "Välj datum för utresan.", "Välj datum för hemresan."), `router.push(searchUrl(…))`, and an optional `initial` search. The fields Utresa/Hemresa and Resenärer are slightly narrower (`md:w-52`, `md:w-44`) to make room.
- **`Autocomplete`**: an optional `initial` item, and Tab chooses the highlighted suggestion (R13, added with the user during the work). Tab and Enter choose only when the list answers the text in the field (`answered`), found in the review; it also fixes the problem noted in TRIP-001's verification, Enter choosing from the previous list. **`DatePicker`**: starts its texts from `value`, and shows `missing` messages after its own.
- **`Card`**: a new size `flush` (no padding), for a card filled by a button.
- **`app/flyg/page.tsx`**: the results page. The search is read inside `<Suspense>`; an invalid search or unknown airport shows the empty form and "Sökningen saknar något. Fyll i formuläret och tryck på Sök."
- **`app/flyg/FlightResults.tsx`**: the simulated search, the status for screen readers ("Söker flyg…", "N flyg hittades"), the steps (Utresa, Hemresa, Din resa), the list with sorting ("Sortera på": Avgångstid, Pris), "Vald utresa" with **Ändra utresa**, and the summary **Din resa** with **Ändra utresa**/**Ändra hemresa**, the total "Totalt för N resenärer: från … kr" and "Snart väljer du plan och klass här." No flights: "Inga flyg kvar den här dagen. Prova ett annat datum i sökningen ovan."
- **`app/flyg/FlightCard.tsx`**: the card and its details (Flygnummer, Från, Till, Datum, Totalt för N resenärer, **Välj**), and `FlightSkeleton`.
- **`lib/search.ts`**: `Search`, `searchUrl()`, `parseSearch()`, `MIN_TRAVELLERS`/`MAX_TRAVELLERS` (moved from the form).
- **`lib/flight-rules.ts`**: `Flight`, `searchDelay()`, `flightNumber()`, `totalPrice()`, `localNow()`, `hasLeft()`, `sortFlights()`.
- **`lib/flights.ts`** (server only): `getAirportPair()`, `findFlights()`.
- **Admin** (R12): `AssignAircraftButton`, `assignAircraftAction`, `getRouteStats`, `assignAircraftToRoutes` and the aircraft table's column Rutter (`routeCount`) are deleted; deleting an aircraft no longer touches routes.

## Decisions

- **The address holds the search** (`fran`, `till`, `utresa`, `hemresa`, `resenarer`, Swedish like the page `/flyg`), so it can be reloaded and shared (R2). The airports are IATA codes, not database ids, so the address stays readable and valid across databases.
- **The page doesn't check that the dates are bookable.** The form does, with the visitor's own today; the server's today can differ near midnight (Vercel runs in UTC). A date in the past gives no flights (they have left); a date too far ahead shows the same timetable, which is harmless.
- **The simulated wait is in the browser,** after the data is loaded, so the server answers fast (R3, the performance requirement). The status is empty on the server and says "Söker flyg…" only when the page has started in the browser (`useSyncExternalStore`): a live region that changes is read aloud, and the tests can see that the timer runs.
- **Tests fake the browser's clock** (`page.clock`) instead of turning the wait off with a setting, so the site has no test switch, and R3 can still be tested. The clock can't be stopped before the page loads: React's streaming of the `<Suspense>` part uses timers. So it runs until "Söker flyg…" shows and is then moved on; R3 stops it there, and runs axe while moving it in small steps, since axe uses timers too.
- **Flight number from route id and departure position,** not stored: stable as long as the departures don't change, which they don't. Identifying a flight for TRIP-011 should use route and time, not the number.
- **The card is one button** with `aria-expanded`, and Välj is in the details outside it, since a button can't hold another button (R6).
- **The sort choice is radio buttons** in a fieldset, styled as a button group: native keyboard handling and "selected" state for screen readers.
- **After Välj or Ändra, focus moves to the next step's heading**, so keyboard and screen reader users know the page changed.
- **The return list shows at once, without a new simulated wait:** the flights were loaded with the outbound ones.
- **TRIP-005's browser tests are deleted** (they tested "Tilldela plan"), and its unit tests R2 (200 routes) and R4 (2–3 departures) are replaced by TRIP-010-R10's. TRIP-004-R1 no longer checks the column Rutter, and TRIP-021-R3's carousel focus test starts from Sök, now the form's last control.
- **The airport helpers** `typeAirport` and `chooseAirport` moved from TRIP-001's test file to `tests/helpers.ts`, since TRIP-010's tests use them too.
